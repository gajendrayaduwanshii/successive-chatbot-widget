## Root-cause verification

### API/infrastructure reliability — Fixed for tested load

Evidence: 69/69 sequential payloads and 24/24 controlled-concurrency payloads; no timeouts versus 46 previously. Oversized 25-item Next cache responses were observed live, so page size was reduced to 10.

### Query understanding overriding topic — Improved

Goal and subject are separate and About intent no longer suppresses a specific subject. Geospatial phrasing returned data/geospatial evidence, but the leading authority was still too broad.

### Primary-topic authority — Improved

Exact title/slug/alias/entity authority was strengthened. Adobe Commerce, Strapi, Modern Data Architecture, Maritime, and ESRI improved. Kubernetes and several newly sampled long titles still expose ranking gaps.

### Content-type compatibility — Improved

Explicit types are eligibility filters. The application-modernization whitepaper now produces only the matching card. Topic-specific webinar and thought-leadership inventory/evidence remains limited.

### Conversation topic switching — Improved, not fixed

Location → agriculture retained the newest subject. FinOps → retail and headless CMS → travel still produced weak or missing evidence in this run.

### Card relevance — Improved

Cards use a stricter authority threshold and are not padded to three. Some business-problem queries still recommend adjacent rather than primary capability pages.

### Broad company/service queries — Improved

Broad service questions now use structurally marked service/pillar content and return an organized portfolio. Canonical About selection remains inconsistent for “Tell me about Successive Digital.”

### Off-topic handling — Fixed for tested deterministic cases

Weather, poetry, movies, and capital-city trivia returned the Successive boundary. Partially related GeoAI/DevSecOps questions were not scope-rejected, though evidence quality varied.

## Implementation and tests

- Added compact, bounded WordPress pagination, corpus caching, shared in-flight builds, stale fallback, partial-collection behavior, and index reuse.
- Removed redundant per-query WordPress searches and relevance-damaging randomization.
- Added structured query dimensions, explicit conversation state, entity authority, hard content-type eligibility, structural broad-service routing, stricter cards, and deterministic off-topic gating.
- Added development-only WordPress/index/cache/LLM/retrieval/request diagnostics.
- Added a live content-derived V2 runner and bounded concurrency checks.
- Automated checks: 81 passed, 9 skipped; typecheck, lint, and production build passed.

## Remaining limitations

- Semantic acceptance is materially better than the previous report’s usable rate, but the generic target is not fully met.
- Cold initialization can still be slow (34.5 s observed once); in-memory caches are per serverless instance and are not a durable shared index.
- Two serial LLM operations can dominate P95 latency; tighter LLM budgets or a persisted/prebuilt compact index are the next reliability step.
- Some natural business problems need stronger capability-first mapping, and long exact titles containing encoded punctuation need better normalization.
- Canonical About, Kubernetes, forestry, thought-leadership, and some topic-specific webinar queries remain regression gaps.
